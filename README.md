# bilibili 每日自动投稿：可行性讨论稿

更新日期：2026-10-24。状态：方案讨论，尚未实现或进行账号实测。

> **2026-10-25 更新**：网页接口路线已实现（`bili_submit/`，纯 HTTP，无浏览器自动化），
> 使用说明见 [USAGE.md](USAGE.md)。真实登录、上传、投稿的账号实测（下文阶段 2/3）仍待执行。

## 已确认的目标

- 在本项目中建立独立的 bilibili 目录。
- 每天自动投稿视频，通过 HTTP 接口实现，不使用 Playwright、Selenium 等浏览器自动化。
- 整体业务目标包含自动选题、其他平台生成短视频及投稿；用户随后明确，当前只讨论 B 站自动化，上游生成留待后续对接。
- 最终运行在服务器，本机通过 Bash 做测试；服务器系统及本机 Bash 类型（WSL / Git Bash 等）尚未确认。
- 投稿路线以稳定性和账号正常使用为优先，用户尚未指定必须走网页接口。
- 先讨论技术可行性，再确定实现范围与路线。

## 可行性结论与证据

协议层自动投稿在技术上可行，已有官方能力和开源实现可供核对。但公开资料不能证明当前账号、部署网络和目标视频已经能够完成投稿。

| 路线 | 已查到的依据 | 落地前需要确认 |
| --- | --- | --- |
| 官方开放平台 API | 官方文档列出账号授权、视频管理等能力；稿件编辑接口要求 ARC_BASE 权限及用户授权 | 开发者入驻、应用审核、投稿权限及目标账号授权是否可取得 |
| 创作中心网页接口 | biliup 文档提供 Cookie 登录、web 投稿、视频查询和定时参数；项目存在 UPOS 上传实现 | 当前账号可用性、请求字段、会话维护、异常响应和接口变化 |

官方 API 同样属于协议层，不要求浏览器自动化。两条路线的鉴权及上传流程应分别实现，不能混用。

资料核对仅完成公开文档层面，尚未发送带账号凭据的请求。

## 投稿路线选择

建议顺序：能取得所需权限时优先官方开放平台；权限不可得时再评估创作中心网页接口。该顺序基于官方接入契约、授权方式和维护成本的工程判断，不是平台公布的风控概率排名。没有可靠公开数据能证明某路线的账号风控概率，不能承诺免风控。

官方稿件能力涉及 ARC_BASE 权限及用户授权。官方接入材料中出现主体证明、应用资料，隐私政策还列出公司名称、营业执照等；“有普通 B 站账号”不能等同于“已经能调用开放平台投稿”。个人当前是否可申请、可取得哪些权限，应以实际开发者后台为准，不能根据一份材料清单断言个人必然可以或不可以申请。

若选择网页接口，建议参考 biliup 当前实现核对协议，显式选择 web 提交方式。biliup 当前文档描述 master 分支已将服务端默认值改为 web，并注明未发布；CLI 默认值与服务端不同，因此不能依赖安装版本的隐含默认值。其关于 app 更易触发风控的描述属于项目维护经验，不能推广成官方统计结论。

优先在稳定的部署环境验证鉴权、上传和投稿，避免生产调度与本地测试同时提交同一任务。平台拒绝、需要重新授权或验证时进入待处理状态，保留任务和素材。

## 当前范围：B 站投稿自动化

用户最新确认：内容方向及其他平台生成短视频后续讨论，当前只考虑 bilibili 自动化。内容生成仍是整体业务的上游，但不在当前设计和实现范围内，暂不需要确定生成模型、画面形式或内容生成预算。

```text
上游平台生成视频
  → 准备完整的视频文件及投稿任务
  → B 站授权检查
  → 视频和封面上传
  → 提交稿件
  → 定时调度及状态回查
```

建议把上游与投稿模块之间的边界设计为一个任务文件或结构化接口，至少包含以下信息：

| 字段 | 用途 |
| --- | --- |
| job_id | 上游分配的稳定任务标识，同一任务重试时保持不变 |
| account_id | 本地账号配置的引用；投稿前核对真实 UID，避免投错账号 |
| video_path | 已准备完成的本地视频路径，文件准备完成后才允许领取 |
| cover_path | 已准备完成的封面路径；是否允许省略取决于路线和产品选择 |
| title / description / tags / category | 投稿元数据，后续映射所选接口字段，分区从当前接口查询 |
| copyright / source | 自制或转载及对应来源信息，按真实内容填写 |
| submit_at / publish_at | 区分计划提交与期望公开时间，时区明确，不能假定两者相同 |
| content_hash | 计算后的文件摘要，用于校验素材及识别误重复，不充当远端幂等保证 |

任务文件与素材准备完成后再原子标记 ready，不能扫描到正在写入的视频就开始上传。若上游只提供下载地址，由接入层先下载并校验成完整文件，再交给投稿模块；当前不实现上游平台 API。

候选技术栈：Python + httpx + SQLite；如果偏好 Go，可用 net/http + SQLite。服务器系统及语言尚未确定，暂不安装依赖。本地 Bash 和服务器使用相同的命令入口与配置约定，Bash 只负责启动，状态和重试逻辑放在程序中。

若服务器为 Linux，可按需要容器化。本机若使用 Git Bash，需兼顾 Windows 路径；若为 WSL，则在 Linux 环境安装依赖。两种 Bash 环境尚未确认。

不同投稿路线实现相同的业务操作：check_auth、upload_video、upload_cover、submit、get_status、reconcile。底层鉴权和上传协议各自独立；只实现选定且已验证的路线，不自动切换到另一条路线重投。

## 网页接口路线的概念流程

```text
读取待发布任务与本地素材
  → 校验文件、元数据、账号及计划时间
  → 检查登录状态
  → 申请上传参数
  → 上传视频分片并完成合并
  → 上传封面
  → 提交稿件元数据
  → 保存平台返回的稿件标识
  → 查询转码、审核与公开状态
```

初始登录可选接口扫码授权或导入已有 Cookie；扫码需要用户在手机上确认，后续日常任务使用保存的会话。是否能够刷新、刷新周期和失效处理，需要按所选登录方式实测，不能假定一次登录永久可用。

上传地址、授权字段和分片大小按服务端返回值处理。封面上传与视频上传完成后，再提交标题、分区、标签、简介及其他必要元数据。具体接口与字段在选定路线后逐项核验，当前不把旧参数列表作为可用结论。

## 每日执行与发布时间

两种目标需要明确区分：

- 每天某时刻提交：系统调度到点启动上传及投稿，公开时间还受网络、转码及审核影响。
- 每天某时刻公开：优先提前上传，验证平台定时发布是否适用于当前路线和账号，并预留审核时间；不能承诺审核一定按时完成。

biliup CLI 文档存在 dtime 定时参数，并描述提交到发布时间需大于 4 小时。这是该工具文档中的条件，实际账号和所选接口的支持情况及限制需要核验，不能直接推广到官方 API。

本地统一使用 Asia/Shanghai 解释计划时间，持久化明确的时区和时间戳。本机 Bash 用于主动执行测试；服务器若为 Linux，可用 systemd timer 或容器中的单一调度进程，最终按部署位置选择。停机错过任务时，应有明确的补发或跳过策略。

## 可靠运行的核心设计

- 用 SQLite 保存任务、文件摘要、账号 UID、上传进度、稿件标识、计划时间、重试次数及最近错误。
- 单账号第一版串行处理投稿任务，使用数据库唯一约束和任务租约，避免多个进程重复领取。
- 本地幂等键可由账号 UID、稳定的内容任务 ID 和发布批次组成；文件摘要用于识别误放的重复素材，明确允许的重复发布由新批次表达。
- 分片上传仅在服务端仍认可当前上传会话时续传；会话失效后重新申请，保留原素材。
- 网络及服务端临时错误采用有上限的退避重试；登录失效进入待授权状态；参数错误进入待修正状态。
- 提交前持久化提交意图。若提交超时或进程在返回结果落库前退出，先进入结果待核对状态，通过自己的稿件列表及可用标识核对，不直接重复提交。无法唯一确认时转人工核对。本地幂等不能保证远端 exactly-once。
- 凭据独立保存在受限本地文件或系统凭据存储中，不写入业务配置示例、日志或版本库。

候选状态流：待处理 → 已校验 → 上传中 → 已上传 → 提交中 → 已提交 → 审核中 → 已公开。异常分支包括待授权、待重试、结果待核对、已退回、待人工处理。实际平台状态需在实现时映射。

## 建议的落地顺序与验收

| 阶段 | 工作 | 完成依据 |
| --- | --- | --- |
| 1 | 确认账号规模、日投稿量、运行环境及 API 权限 | 明确可接入的投稿路线和上游任务输入 |
| 2 | 实现登录检查和自己的稿件查询 | 真实响应确认目标账号与授权有效，不产生投稿 |
| 3 | 独立验证一条视频的上传、投稿及状态跟踪 | 记录真实稿件标识，分别确认审核及最终公开或退回；HTTP 200 不等于发布成功 |
| 4 | 加入任务队列、每日调度及恢复机制 | 检查上传恢复、超时核对、重启及重复调度行为 |
| 5 | 在目标服务器验证每日投稿 | 连续多日记录任务、稿件标识及实际平台状态；上游生成对接另行讨论 |

当前完成：专用目录、公开资料核对、投稿候选方案及上游接入边界。当前未完成：登录、接口实测、真实上传、真实投稿、审核跟踪及每日运行验证。上游内容生产当前暂缓讨论。
